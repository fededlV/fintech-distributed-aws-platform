# 🛠️ Troubleshooting & Incident Runbook — `api-clients`

[![Component](https://img.shields.io/badge/Service-api--clientes-3776AB)](README.md)
[![Status](https://img.shields.io/badge/Runbook-Operational-success)](README.md)

This runbook documents operational errors, permission anomalies, and database configuration issues encountered during the containerization and testing of the **Customer Management Service** (`api-clients`), along with tested resolutions.

---

## 📋 Issue Log & Solutions

### 1. Missing Library / Command `flask` Not Found in Multi-Stage Image
* **Symptom**: The container exits immediately on boot with `ModuleNotFoundError: No module named 'flask'` or `command not found: flask`.
* **Root Cause**: Python dependencies were installed inside `/opt/venv` during the `builder` stage, but the `runner` stage was referencing global system binaries because the virtual environment was not prioritized in the system path.
* **Resolution**:
  Explicitly prepended the virtual environment directory to the container `PATH`:
  ```dockerfile
  ENV PATH="/opt/venv/bin:$PATH"
  ```
  This ensures that the Python runtime and all CLI wrappers point to the isolated `/opt/venv` binaries.

---

### 2. Filesystem Permission Denial under Non-Root User (`appuser`)
* **Symptom**: Runtime errors when Flask attempts to create cache files, write logs, or access application assets (`Permission denied`).
* **Root Cause**: The application files were copied into `/app` under the default root owner before switching to `USER appuser`.
* **Resolution**:
  Applied recursive user ownership before dropping privileges:
  ```dockerfile
  RUN chown -R appuser:appuser /app
  USER appuser
  ```

---

### 3. Database Connection Failure & Hostname/Port Misconfiguration
* **Symptom**: Creating a customer record fails with `OperationalError: (2003, "Can't connect to MySQL server")`.
* **Root Cause**: The service `.env` file was erroneously configured with the host-facing port and `localhost` rather than the internal Docker bridge network alias (`DB_HOST=db`, `DB_PORT=3306`).
* **Resolution**:
  Updated the configuration file (`envs/api-clientes.env`):
  ```ini
  DB_HOST=db
  DB_PORT=3306
  DB_NAME=db_clientes
  DB_USER=usuario_app
  DB_PASSWORD=secreto
  ```
  Restarted the container stack with `docker compose down && docker compose up -d` to establish internal network communication.

---

### 4. Database Authentication / Schema Authorization Error
* **Symptom**: HTTP 500 error on customer creation: `Access denied for user 'usuario_app'@'%' to database 'db_clientes'`.
* **Root Cause**: Mismatch between the initial credentials generated by the MariaDB bootstrap script (`db/init-scripts/00-databases.sh`) and the local credentials in `.env`.
* **Resolution**:
  Synchronized `.env` credentials with the MariaDB user privileges and restarted the database container with volume persistence intact.
